## 2026-08-25 — 正文拖拽选择失控全选时间线：user-select contain 围堵

- 目标：用户在 Android APK 里拖动正文选择手柄复制文字时，选区失控扩大到整个时间线（上下所有消息被全选）。
- 根因：Chromium/WebView 已知缺陷——拖动选择端点扫过 `user-select: none` 内容（全局 styles.css 对 button/label 设置；正文的「可优化」段间按钮、消息下方反馈行、插画卡片按钮都是此类障碍物）时，Blink 无法在该落点建立选区端点，把端点归一化到最近可选中祖先边界，最坏跳到文档头尾形成全选。
- 关键改动（纯 CSS，方案 A）：`.timeline-entry` 与 `.story-prose` 加 `-webkit-user-select: contain; user-select: contain`，强制选区被限制在单条消息/单条正文内部，跨条扩散被浏览器钳制；`.story-prose p` 与 `.user-message-text` 显式声明 `user-select: text`，保证文本区域命中测试始终解析到可选中的目标。备选方案 B（selectionchange JS 兜底，补丁式）与 C（段间按钮移出文本流根治触发面）暂不采用。
- 验证：`npm run build`（tsc -b + vite build）通过。真机效果待用户安装验证。
- 残余风险：这是对上游 WebView 缺陷的围堵而非根治——若真机上选区仍在单条消息内乱跳（例如跨过段间「可优化」按钮时），需要实施方案 C 把按钮移出段落间文本流。

## 2026-08-25 — 漏检标记可撤销、面板内导出，与导出权限根因修复（save→share）

- 目标：用户三问——手误标注能否取消、标注数据如何导出、原 JSON 导出因存储权限失败是否已修。三个都未覆盖，本批一次补齐；权限是另两项的前置（漏检导出走同一保存通道）。
- 根因（读 @capgo/capacitor-file-sharer 8.0.0 Android 源码确认）：`FileSharer.save()` 在 Android ≥10 走 MediaStore 免权限，但 Android ≤9 走 `saveLegacy` 直写公共目录、必须 `WRITE_EXTERNAL_STORAGE` 运行时授权——应用从未申请；且 `saveDirectory:'documents'` 实际落入 Downloads 集合（插件 collectionUri 仅识别 pictures/movies/music），与用户预期「Documents/叙影」不符。ProseEvaluationDialog 的「请检查设备存储权限」文案是 catch-all，掩盖了真实错误形态。
- 关键改动：
  - `providers/evaluationExport.ts`：`saveEvaluationReport` 原生分支从 `FileSharer.save` 改为 `FileSharer.share`——写应用私有缓存 + FileProvider URI + 系统分享面板，全 Android 版本零权限，目标可选（保存到文件/微信/剪贴板等）；android saveDirectory 选项随之移除。对话框错误文案改为「导出失败，请重试或改用预览后手动复制」。评估报告导出同路径受益。
  - 取消标注：`storyDatabase.ts` 新增 `deleteMissedFlavorReport(paragraphId)`（按段落幂等删除）；`ParagraphPickList` 已记下行右侧显示撤销按钮（RotateCcw），点击删库并恢复该行可选；撤销行同样先展开全文再决定。
  - 面板导出：MissedFlavorPanel 底部新增「导出全部记录」，拉取全表序列化为 `{exportedAt, count, reports[]}` JSON（含正文全文），文件名 `叙影-AI味标记-YYYY-MM-DD.json`，走修好的 share 通道；空表时提示不导出。
  - 行布局从 grid 两列改 flex（选择钮 flex:1 + 右侧动作钮 auto），兼容展开+撤销双按钮行。
- 验证：`npx tsc -b` 通过；全量 `npx vitest run --no-file-parallelism` 58 文件 603 项通过；`npm run build` 通过。App.test.tsx mock 补 deleteMissedFlavorReport。
- 残余风险：① 真机验证待用户装新 Debug 包——重点确认分享面板弹出与「保存到文件」落盘位置符合习惯（不再固定 Documents/叙影）；② 导出的标记 JSON 含正文，提醒勿外发到不可信渠道；③ share() 在无任何分享目标的极端 ROM 上会 ERR_ACTIVITY_NOT_FOUND，届时 UI 显示重试提示。

- 关键改动：在统一供应商能力层新增 `structuredOutput`，自动兼容使用覆盖面较广的 `json_object`，OpenAI 官方使用严格 `json_schema`，严格中转保留纯提示词协议，自定义设置可显式选择；前台流式/非流式写作与 Android 后台写作复用同一个请求构造，不支持时不自动重发，避免重复计费。严格 schema 覆盖正文、场景记忆与视觉计划，所有对象均关闭额外字段并要求已声明字段；无图模式不包含 `visual_plan`。旧版官方/严格预设即使没有新字段，也继续兑现各自的 schema/纯提示词行为。
- 提示与诊断：系统提示要求对白优先使用中文弯引号，ASCII 双引号与控制字符必须按 JSON 规则转义；结果解析区分“对白引号未转义”“JSON 尾部截断”“其他格式错误”，提示不泄露模型正文。损坏段落不再把未转义引号前的半段误当作完整正文，已闭合的前序段落仍可安全恢复。
- 原因：旧链路只用提示词要求 JSON，接口层没有结构化约束；模型或中转站在正文字符串中写入裸英文双引号后，严格 `JSON.parse` 必然失败。自动探测中转站是否支持 schema 没有可靠元数据，失败后自动改参数重试又可能重复计费，因此采用显式能力分层而非猜测或自动重发。

## 2026-08-10 — Android 生图完整性误判修复

- 查明 Android 生图保存报“图片文件不完整”的根因：`CapacitorHttp` 对 `arraybuffer` 使用 Android `Base64.DEFAULT` 返回，内容会每 76 个字符带 CR/LF。此前传输层仅把无空白字符串识别为 base64，因而将带换行的完整 base64 再次 `btoa`，把 ASCII base64 文本误写入图片文件。
- 图片二进制响应、data URL 解析和持久化写入现在都会移除 base64 空白并规范化 URL-safe 字符与 padding；分块写入仍保持 4 字节对齐，文件头尾完整性校验未放宽，截断 PNG 仍会拒绝保存。
- 新增 Android CR/LF `arraybuffer` 响应、带换行图片 data URL 分块写入和截断 PNG 拒绝测试；同源 Bearer 与跨域匿名 URL 的既有安全边界未改变，未恢复无鉴权 `Filesystem.downloadFile`。
